# 22 资源预算与容量规划

## 概述

本文档汇总 esp-claw 各子系统的关键资源限制常量，帮助开发者在 ESP32 上做内存和任务预算，以及在移植到 PC 时评估哪些参数应当放大。

---

## 1. FreeRTOS 任务栈大小与优先级

| 组件 | 常量 | 默认值 | 来源文件 |
|------|------|--------|---------|
| `claw_core`（Agent 循环）| `CLAW_CORE_DEFAULT_STACK_SIZE` | **8 KB** | `claw_core.c` |
| `claw_core` 任务优先级 | `CLAW_CORE_DEFAULT_PRIORITY` | 5 | `claw_core.c` |
| `claw_event_router` 任务栈 | `CLAW_EVENT_ROUTER_DEFAULT_STACK` | **8 KB** | `claw_event_router.c` |
| `claw_event_router` 任务优先级 | `CLAW_EVENT_ROUTER_DEFAULT_PRIO` | 5 | `claw_event_router.c` |
| 异步记忆萃取任务栈 | `CLAW_MEMORY_ASYNC_EXTRACT_STACK_SIZE` | **6 KB** | `claw_memory_session.c` |

> 所有任务默认使用 `CLAW_TASK_STACK_PREFER_PSRAM` 策略，即优先将栈放入 PSRAM（若可用）。

## 3. claw_cap 的容量与增长策略

初始容量和增长步长均使用相同常量：

| 参数 | 初始值 | 增长步长 | 常量 |
|------|--------|---------|------|
| 能力描述符（descriptor）| **4** | **4** | `CLAW_CAP_DEFAULT_MAX_CAPABILITIES` |
| 能力组（group）| **4** | **4** | `CLAW_CAP_DEFAULT_MAX_GROUPS` |

增长逻辑（两个数组均采用相同模式）：

```c
new_capacity = s_runtime.descriptor_capacity
               ? s_runtime.descriptor_capacity : CLAW_CAP_DEFAULT_MAX_CAPABILITIES;
while (new_capacity <= s_runtime.descriptor_count) {
    growth_margin = new_capacity / 2;
    if (growth_margin < CLAW_CAP_DEFAULT_MAX_CAPABILITIES) {
        growth_margin = CLAW_CAP_DEFAULT_MAX_CAPABILITIES;
    }
    new_capacity += growth_margin;
}
```

即**每次容量不足时按 50% 增长（最小增量为 4）**，直到满足需求。

## 6. claw_ramfs 配置项

`claw_ramfs` 是一个纯内存文件系统，通过 `claw_ramfs_register()` 挂载，无全局默认值，**全部由调用者配置**：

```c
typedef struct {
    const char *base_path;  // VFS 挂载点，如 "/ram"
    size_t max_files;       // 最大同时打开文件数
    size_t max_bytes;       // 文件内容总字节上限
    uint32_t caps;          // 堆内存能力标志（MALLOC_CAP_INTERNAL 或 MALLOC_CAP_SPIRAM）
} claw_ramfs_config_t;
```

限制：
- 最多同时挂载 **4** 个 RAMFS 实例（`CLAW_RAMFS_MAX_INSTANCES = 4`）
- 文件名最大 255 字节（`NAME_MAX`）

## 8. 移植到 PC 时的放大建议

移植到 PC（Linux/macOS/Windows）后，内存已不再受限，以下常量可以安全放大，并能带来明显收益：

| 常量 | ESP32 值 | PC 建议值 | 放大收益 |
|------|---------|---------|---------|
| `CLAW_CORE_DEFAULT_STACK_SIZE` | 8 KB | 64–256 KB | 防止深递归和大型 JSON 操作栈溢出 |
| `CLAW_EVENT_ROUTER_DEFAULT_STACK` | 8 KB | 64 KB | 事件处理中的复杂规则执行 |
| `CLAW_CORE_DEFAULT_REQUEST_Q` | 4 | 32–64 | 支持高并发请求（Web 服务场景）|
| `CLAW_EVENT_ROUTER_DEFAULT_QUEUE_LEN` | 6 | 32–64 | 高频事件不丢失 |
| `CLAW_MEMORY_SESSION_SIZE_LIMIT` | 150 KB | 10–50 MB | 超长对话历史 |
| `CLAW_MEMORY_MAX_ACTIVE_ITEMS` | 128 | 10000+ | 大规模长期记忆 |
| `CLAW_CAP_CORE_OUTPUT_SIZE` | 32 KB | 1–4 MB | 工具返回大型文档/图像 base64 |
| `CAP_LUA_MAX_SCRIPT_SIZE` | 16 KB | 1 MB | 支持较大 Lua 脚本文件 |
| `CAP_LUA_ASYNC_MAX_JOBS` | 16 | 256 | 多脚本并发管理 |
| `CLAW_RAMFS_MAX_INSTANCES` | 4 | 16 | 更多临时文件系统挂载点 |
| `CLAW_MEMORY_COMPACT_SIZE_THRESHOLD` | 32 KB | 1 MB | 减少压缩频率，降低 I/O 开销 |

### 特别说明

- **任务栈**：PC 上可直接使用 POSIX 线程，栈大小由 `pthread_attr_setstacksize` 控制，通常 256 KB 以上无特别问题。
- **队列长度**：PC 上内存充裕，但队列长度增大会增加请求堆积风险，需配合合理的超时策略。
- **SESSION_SIZE_LIMIT**：ESP32 上 150 KB 是 PSRAM 限制的折中，PC 上 10 MB 以上完全可行，适合需要长上下文的应用。
- **CLAW_CAP_CORE_OUTPUT_SIZE**：32 KB 是 ESP32 内存紧张时的折中，PC 上如需返回长文档（如代码生成、RAG 检索），建议放大到 1–4 MB。
