## Overview

`cap_web_search` exposes the `web_search` tool to the LLM, allowing the Agent to search through an explicitly selected provider. It supports **Bocha**, **Tavily**, and **Brave Search**.

## Tool description

| Tool ID | Description |
|---------|-------------|
| `web_search` | Search the web and return concise formatted results |

### Input parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `query` | string | Yes | Search keywords |

### Return value

Returns formatted search result text containing titles, summaries, and links. By default it returns the first 5 results.

## Search providers

| Provider | NVS config key | Description |
|----------|----------------|-------------|
| Bocha | `bocha_key` | Bocha web search with summaries |
| Tavily | `tavily_key` | Default for new configurations |
| Brave Search | `brave_key` | Brave web search |

Select the search provider in web settings (`search_provider`: `bocha` / `tavily` / `brave`), enter its key, save, and restart. Legacy settings without a saved selection retain Tavily or Brave according to the previous rules; saving fixes the selection.

<Aside type="note">
  The selected provider must have an API key. Missing keys or failed requests return an error without switching to another provider.
</Aside>

## Registration and configuration

```c
#include "cap_web_search.h"

ESP_ERROR_CHECK(cap_web_search_set_provider("bocha"));
ESP_ERROR_CHECK(cap_web_search_set_bocha_key("your-api-key"));
ESP_ERROR_CHECK(cap_web_search_register_group());
```

API keys are usually read from NVS by the application layer, then passed to the corresponding `set_*_key` function.
